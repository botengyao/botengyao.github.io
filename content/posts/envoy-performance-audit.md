*These are notes from a static read of the code. Nothing here has been benchmarked yet, and some of it will turn out to be wrong.*

I set out to check five areas of Envoy for performance: the common utilities, C++ usage, string handling, header and value handling, and the QUICHE codecs. The largest items turned out to sit outside that list. The release build has no PGO or LTO. A small TLS request costs three `recv` calls where one would do. And a default request performs about 110 atomic operations on shared cache lines and about 80 avoidable small allocations, which trace back to a handful of patterns.

**How this was done.** The audit ran against upstream `main` at `4c860781ae`. Claude read the code in fourteen parallel sweeps, one per subsystem, and then re-read the top claims against the tree in a second pass. A finding marked **verified** went through that second read. One marked **reported** came from a sweep and was not re-checked. Thirteen sweeps finished; the HTTP/1 and HTTP/2 codec sweep did not, so that section is partial. Every gain below is an estimate, and each section names the benchmark that would confirm it. A few items were first seen in an earlier pass in August and are marked as open since then.

Each finding carries an ID, an impact (High, Medium or Low), an effort (S, M or L) and a status. Paths are relative to the Envoy repository root.

## Summary

Fifteen changes carry most of the available gain. They are ordered by expected payoff against effort and risk, which is also the suggested order for pull requests.

| # | Change | Findings | What it removes | Effort |
| --- | --- | --- | --- | --- |
| 1 | Measure PGO and ThinLTO on the release build | BLD-1, BLD-2 | No source change. Upstream measured 21% more requests per second from PGO alone. | L, build and CI |
| 2 | Land the TLS write realignment fix | IO-3 | A 16 KB allocation and copy per TLS record: a median 10.3% less CPU on the affected path | S |
| 3 | Non-owning thread-local slot accessor | TLS-1 | About 48 atomic operations per request, 20 of them on one line shared by all workers | S |
| 4 | Read-ahead in the TLS BIO | IO-1 | Two of three `recv` calls per small TLS read, one of two per record in bulk | M |
| 5 | Lazy stream idle timer | HCM-1, UPS-7 | 9 of 16 libevent timer calls per request and all per-chunk timer work | S, then M |
| 6 | Circuit-breaker accounting | STR-1, UPS-3 | 4 of 7 runtime lookups and 4 shared gauge writes per request | S |
| 7 | A batch of local fixes on the default path | CPP-1, CPP-2, UPS-1, HCM-5, STATS-7, CPP-5, CPP-6, CPP-7, UTIL-1, HCM-8 | About 40 allocations, 2 reader locks and 60 to 100 out-of-line calls per request | S each |
| 8 | Stop the read loop on a short read | IO-2, IO-4 | One `readv` per plaintext read event; two `epoll_ctl` per read-disable toggle | M, touches close detection |
| 9 | Header node pool and cheaper accessors | HDR-1, HDR-2, HDR-3 | About 20 allocations per request and the lazy map build | M |
| 10 | `shared_ptr` by reference from host pick to pool-ready | CPP-3, CPP-13 | About 40 atomic operations per request on shared control blocks | M, interface signatures |
| 11 | Counter update in one atomic operation | STATS-4 | Two of every three locked operations per counter update | M, hot-restart tests |
| 12 | Per-worker batching for file access logs | ALOG-1 | A process-wide mutex per log line | M |
| 13 | UDP receive buffer reuse | QUIC-1, QUIC-4, QUIC-5 | About 100 allocations and one syscall per UDP read event | S, then M |
| 14 | AI protocol manager: skip untouched bodies | EXTB-2, EXTB-1, EXTB-3 | Request re-serialization and the whole response pipeline when no filter needs them | S, M, M |
| 15 | Side-call helpers | EXTA-1, EXTA-2, EXTA-7, HCM-9 | A process-wide reader lock, a timer re-arm and several allocations per ext\_authz or ratelimit call | S each |

Three larger pieces need a design before code: ref-counted buffer slices (CODEC-1, CODEC-2, NET-1), running libevent without its lock (STATS-12), and a per-cluster memo for response-code stats (STATS-3).

Two measurement gaps block sizing most of this. There is no benchmark that sends a request through a real `ConnectionManagerImpl` and router, and the shared-cache-line items need `perf c2c` on a multi-worker load test.

The avoidable calls are the `EAGAIN` probe that ends every read loop (IO-2) and the separate 5-byte header read BoringSSL makes for each TLS record (IO-1).

Syscalls aside, the cost of the default path is spread over five kinds of small operation. The counts are for one proxied HTTP/1 request with default configuration, taken from reading the code.

| Kind of work | Per request | Main sources | Findings |
| --- | --- | --- | --- |
| Small heap allocations | about 80 avoidable: 34 in the HCM and router, about 25 header nodes, 7 in the pool lookup, 6 each in stream info and timer creation | list nodes, unreserved vectors, closures, objects for unused features | HDR-1, HCM-4, UPS-1, CPP-5, CPP-6, STATS-7, ALOG-5 |
| Atomic operations on lines all workers share | about 110: 50 from `shared_ptr` copies, 20 from the runtime snapshot, 40 from counter and gauge updates | by-value `shared_ptr`s, thread-local slot access, three-operation counters | CPP-3, TLS-1, STATS-4, CPP-1 |
| libevent timer calls | 16, each under the base mutex | idle timer re-arm, route timeout, connection idle timers | HCM-1, UPS-4, STATS-12 |
| Clock reads | about 25 | adjacent timing points that each read the clock | CPP-10 |
| String-keyed lookups | about 25: 10 runtime keys, 6 to 8 feature-flag names, 8 dynamic stat names | circuit breakers, feature flags, response-code stats | STR-1, STATS-9, STATS-3 |

## Header map and header/value handling

Each header costs one 304-byte heap node, so a proxied request allocates about 25 nodes across its request and response maps. That and the indirect calls behind every well-known-header accessor are most of the header map's own cost. The rest sits at call sites that copy values or repeat lookups.

### Header map implementation

- **HDR-1** (High · M · verified). The header list is a `std::list<HeaderEntryImpl>` (`source/common/http/header_map_impl.h:315`). An entry holds two `HeaderString`s with 128-byte inline buffers, so a node is 304 bytes, and every header, well-known or not, is its own allocation. **Change:** Keep the list (stable pointers, O(1) erase) and give it a per-map node pool, with the first chunk carved from the map's existing allocation. Declare `entry_` before `key_` to touch one cache line fewer.
- **HDR-2** (Medium · S · reported). A well-known-header accessor through the interface is two to four indirect calls and four dependent loads: virtual `X()`, a `std::map` iterator inside the handle, virtual `constInlineHeaders()`, virtual `value()` (`header_map_impl.h:25`, `:434`). `mutateRequestHeaders` alone makes 39 such calls, 27 of them `removeX()` of headers that are normally absent. **Change:** Cache the slot index in the handle; expand the accessor macros against the slot array in the four `final` map classes; mark `HeaderEntryImpl` `final`.
- **HDR-3** (Medium · S · verified). The first by-name `get` or `remove` of a non-inline header, on a map with three or more headers, builds a hash map over every header, including the well-known ones it never serves (`source/common/http/header_map_impl.cc:26`, `:56`). Every later insert then pays a hash. Triggered by every HTTP/3 request, trace propagation headers, custom-header route matchers and `request_headers_to_remove`. **Change:** Build adaptively: scan the list until the map has answered several non-inline lookups. Do not index well-known headers.
- **HDR-5** (Medium · S · verified). Setting a header by name is `remove` then `add`: two static lookups, a node free and a node allocation (`header_map_impl.cc:317`). **Change:** On a static hit use the slot path; with exactly one existing entry, overwrite in place. The header then keeps its position, as it does for typed setters.
- **HDR-6** (Medium · S · verified). `HeaderParser::evaluateHeaders` copies every configured value, static or formatted, into a staging `std::string`; `addReferenceKey` then copies it twice more (`source/common/router/header_parser.cc:185`, `:238`). **Change:** Stage `string_view`s. Static values can go in by reference, as the key already does.
- **HDR-7** (Medium with `normalize_path` · S · reported). `canonicalPath` has no exit for clean paths: a runtime flag, two scans, then googleurl (adds to STR-6). **Change:** One table-driven pre-scan that returns when no byte can change.
- **HDR-4** (Low with libc++ on Linux · S · verified). `iterate()` constructs its `std::function` twice (CPP-14). libc++ on Linux keeps closures up to 24 bytes inline, so the HTTP/1 encode closure allocates only under libstdc++ and on macOS. ext\_authz's 56-byte closure allocates twice everywhere. **Change:** `std::move` in the wrapper now; `absl::FunctionRef` for the interface.
- **HDR-8** (Low · S · reported). `:status` is parsed from text four to six times per response across codec, router, filter manager and HCM (`source/common/http/utility.cc:657`). `requestHeadersValid` runs twice for HTTP/1 downstream. **Change:** Carry the numeric code beside the map; read the method once per helper.
- **HDR-9** (Low · S · verified for `path_utility.cc`). Three runtime flags read by name per request on the HCM header path, added after [#46591](https://github.com/envoyproxy/envoy/issues/46591) (`source/common/http/conn_manager_utility.cc:384`, `:740`; `source/common/http/path_utility.cc:35`). **Change:** Latch them where [#46591](https://github.com/envoyproxy/envoy/issues/46591) latched the others.
- **HDR-10** (Low · S · reported). The static lookup copies a `std::function` out of the trie on every hit (`source/common/common/compiled_string_map.h:36`). No allocation, but seven to nine indirect calls per well-known header. Open since August. **Change:** Store a pointer to the registry entry.

### Call sites

- **HUSE-1** (Medium · M · verified). HTTP/2 encode copies every owned header name and value into a `std::string`, only to tell the adapter to copy it (`source/common/http/http2/codec_impl.cc:342`). nghttp2, still the default, then copies the bytes again. Six to ten allocations per header block, twice per request when both hops are HTTP/2. **Change:** A third `HeaderRep` alternative in QUICHE meaning "view, copy required", or one per-stream buffer for the owned strings.
- **HUSE-6** (Medium · S · reported). `traceparent`, `tracestate` and the `b3` headers are not registered as inline headers. Every request on a tracing-enabled HCM does a generic `get` and a remove-plus-add for each, sampled or not, and OpenTelemetry inject builds three strings (`source/extensions/tracers/opentelemetry/tracer.cc:120`). **Change:** Register them with `RegisterCustomInlineHeader`; format `traceparent` into a stack buffer.
- **HUSE-5** (Medium on header-matched tables · M · reported). Route matching repeats the same header lookup for every candidate route. `RouteMatchContext` caches path, query and cookies, not headers. HCM-8 covers the ordering half. **Change:** Memoise header lookups per request in the context.
- **HUSE-7** (Medium for those configs · M · reported). With `upstream_log` on the router, the response headers and trailers of every upstream response are deep-copied (`source/common/router/upstream_request.cc:329`). **Change:** Copy only when a configured logger reads response headers.
- **HUSE-10** (Low · S · reported). `LowerCaseString` is built per request from config-lifetime or literal strings at about 20 sites, usually followed by `addCopy`: jwt\_authn `claim_to_headers`, basic\_auth, mcp\_router. **Change:** Hold a `LowerCaseString` in the config and use `addReferenceKey`.
- **HUSE-11** (Low · S · reported). The fault filter formats five runtime keys per request when `x-envoy-downstream-service-cluster` is present, before it knows a fault applies (`source/extensions/filters/http/fault/fault_filter.cc:147`). **Change:** Format each key in the branch that uses it.

Smaller call-site items, all Low: oauth2 parses the Cookie header three times per request (HUSE-9); ratelimit allocates an empty response header map per OK response (HUSE-14); CEL header lookups copy the key twice (HUSE-15); grpc\_stats does a generic lookup of `connect-protocol-version` on every request (HUSE-17); XFF on internal hops is parsed into a new address object per request (HDR-11).

`header_map_impl_speed_test` lacks the cases these need: a decode-shaped populate of about 12 mixed headers, accessors called through `const RequestHeaderMap&`, `removeX()` of an absent header, and lookups after populate at several counts.

## Common critical utilities

Every thread-local slot access copies and destroys a `shared_ptr`, which is two atomic operations for what should be a pointer read. For the runtime snapshot those atomics hit one cache line shared by all workers, about twenty times per request.

- **TLS-1** (High · S · verified). `ThreadLocal::Slot::get()` returns the stored `shared_ptr` by value (`source/common/thread_local/thread_local_impl.cc:90`). `getTyped<T>()` and `TypedSlot::operator->` call it and drop the copy on every access (`envoy/thread_local/thread_local.h:46`, `:165`). `Runtime::Loader::snapshot()` goes through it, and every worker's slot holds the same snapshot object (`source/common/runtime/runtime_impl.cc:667`). The default path calls `snapshot()` about ten times per request (see STR-1). **Change:** A non-owning accessor that returns `ThreadLocalObject&`, used by `getTyped` and `TypedSlot`. Lifetime is unchanged: the slot keeps its own reference, and `getTyped` already hands out a reference that outlives the temporary.
- **UTIL-1** (Medium · S · verified). Every disabled `ENVOY_LOG`, `ENVOY_CONN_LOG` and `ENVOY_STREAM_LOG` first calls `Context::useFineGrainLogger()`, defined out of line in `source/common/common/logger.cc:165`. With no LTO that is a real call at each of the 60 to 100 log sites a request passes. **Change:** Keep the flag in a header-visible `std::atomic<bool>` and inline the check.
- **UTIL-3** (Medium · M · verified). Per-request objects are linked through `std::list<std::unique_ptr<T>>` (`source/common/common/linked_object.h:22`): one extra list-node allocation each for the HCM stream, upstream request, codec client request and HTTP/2 streams. Three to five per request. **Change:** Move those types to the `IntrusiveListNode` already in the same file, used today only by dubbo and generic\_proxy.
- **UTIL-8** (Medium · L · reported). Every RE2 match takes a reader lock on that regex's DFA cache mutex, shared by all workers (`source/common/common/regex.h:35`, RE2 `dfa.cc:1768`). A request that walks 50 regex routes touches 50 shared lines. **Change:** Measure with a threaded benchmark first. Then per-worker clones, or one `RE2::Set` prefilter per virtual host.
- **UTIL-6** (Medium on matcher configs · S · reported). The matcher API's query-parameter input parses and decodes the whole query string for every predicate (`source/common/http/matching/inputs.h:168`). Classic routes cache this in `RouteMatchContext`; the matcher path does not. **Change:** Scan the raw query for the one key.
- **UTIL-7** (Medium for dynamic subset routing · S · reported). `HashedValue` is built per request for dynamic `envoy.lb` metadata: two deep copies of the `Value` and a reflection-based hash (`source/common/protobuf/utility.h:718`). **Change:** Hash `google.protobuf.Value` with a `kind_case()` switch; take the value by move.
- **UTIL-5** (Low to Medium · S and M · reported). Generic matcher: a map-matcher miss runs the data input a second time (`source/common/matcher/map_matcher.h:19`); each result copies the action `shared_ptr`; prefix lookups copy a `shared_ptr` per matching prefix. **Change:** Pass the availability down; hold the action by pointer; return `const Value*` from the radix tree.
- **UTIL-10** (Low to Medium · M · reported). IP matchers receive the address as text, copy it and parse it back into a heap `Address::Instance` per evaluation (`source/extensions/matching/input_matchers/ip/matcher.cc:39`). **Change:** Parse into a stack `sockaddr` and query the trie on the raw address.
- **UTIL-9** (Low to Medium · S · reported). Date formatters keep one second per format in a thread-local cache and return it by value (`source/common/common/utility.cc:623`). Requests that last longer than a second miss the cache on most log lines. **Change:** An `appendTo` API; keep a few recent seconds per formatter.
- **UTIL-14** (Low to Medium · M · reported). `Json::Factory::loadFromString` on data paths builds a config-grade DOM: two or more allocations per value, strings copied twice, one runtime flag read per parse (`source/common/json/json_internal.cc:745`). Used per message by `mcp_router`, `json_to_metadata` and the JSON content parser. **Change:** A view-based entry point with one allocation per field, or the streaming extractors that already exist.

Smaller items, all Low and S: `replaceAllEmptySpace` runs a six-key `StrReplaceAll` for every `%RESPONSE_CODE_DETAILS%` field, clean or not (UTIL-13); `Metadata::metadataValue` builds a `std::vector<std::string>` for one key (UTIL-15); the JSON sanitizer sends valid non-ASCII text through nlohmann, about 20 times slower than the fast path (UTIL-16); the filter-state string matcher calls `serializeAsString()` per match (UTIL-12).

### Stats, runtime flags, event loop and timers

Timer re-arming is under HCM-1 and clock reads under CPP-10; this table holds the rest.

- **STATS-4** (Medium · M · verified). `CounterImpl::add` is three locked operations: the value, a pending increment kept for the flusher, and a "used" flag that is already set (`source/common/stats/allocator.cc:152`). Gauges do two. A request makes about 15 counter and 14 gauge updates. **Change:** Set the flag only when clear; derive the pending delta on the main thread from a latched value. Hot restart and reset semantics need tests.
- **STATS-3** (Medium · M · reported). Router response-code stats are eight dynamic lookups per upstream response: six counters and two histograms, each a name join, a scope-cache probe and a stat-name hash (`source/common/http/codes.cc:48`, `source/common/stats/thread_local_store.cc:700`). The joins no longer allocate. **Change:** A lazily filled per-cluster memo of counter pointers. Stats are still created on first use.
- **STATS-7** (Medium · S · verified). `createTimer` costs four allocations and two frees: the dispatcher wraps the callback in a lambda that copies the `std::function`, and `TimerImpl` copies it twice more (`source/common/event/dispatcher_impl.cc:253`, `source/common/event/timer_impl.cc:12`). Two timers are created per request, and file events do the same per connection. **Change:** `std::move` through the constructors; touch the watchdog in the libevent trampoline in place of the wrapper.
- **STATS-12** (Medium · L and M · reported, open since August). libevent takes its base mutex on every call, about 30 lock pairs per request, and timers sit in one pointer min-heap (`source/common/event/libevent_scheduler.cc:34`). Upstream [#5703](https://github.com/envoyproxy/envoy/issues/5703) saw about 5% in Nighthawk from running without the lock. **Change:** `EVENT_BASE_FLAG_NOLOCK` needs an Envoy-owned wakeup for `post()` and `exit()`. Common-timeout queues for the few dominant durations make arm and disarm O(1).
- **STATS-10** (Medium on those configs · S · reported). `Snapshot::featureEnabled` for a `FractionalPercent` copies the proto twice and always draws a random number, even at 0% or 100% (`source/common/runtime/runtime_impl.cc:159`). Per request for local\_ratelimit, ext\_authz, tracing sampling, CORS and route `runtime_fraction`. **Change:** Select a `const FractionalPercent*` and return early at either end.
- **STATS-9** (Low · M · verified for the macro). Six to eight `runtimeFeatureEnabled` name lookups per request remain on the default path, about 11 ns each. The cached-flag macro from [#48660](https://github.com/envoyproxy/envoy/issues/48660) covers three call sites and still makes four virtual calls per read (`source/common/runtime/runtime_features.h:58`). **Change:** Have the macro resolve once to the typed `absl::Flag<bool>` and read it with `absl::GetFlag`. Runtime overrides still apply at once.
- **STATS-13** (Medium at 100k stats · M · reported). Flush at scale: every histogram ever used is merged and refreshed each interval even with no new samples, and a metric snapshot is built with zero sinks (`source/common/stats/thread_local_store.cc:1242`, `source/server/server.cc:186`). Linear in stat count. Related upstream work is in [#47614](https://github.com/envoyproxy/envoy/issues/47614). **Change:** Skip empty histograms; latch without a snapshot when there are no sinks.
- **STATS-11, STATS-14** (Low · S · verified for the watchdog). The watchdog `touch()` runs a compare-exchange on every event callback (`source/server/watchdog_impl.h:26`). `Stats::Utility::*FromElements` heap-joins names before the scope joins them again. **Change:** Load before store; use the inline joiner.

## C++ usage patterns

About fifty atomic operations per request land on cache lines that every worker shares, almost all from `shared_ptr`s passed or returned by value. Another 25 to 35 small allocations per request come from node containers, unreserved vectors and `std::function` closures. Counts are from reading the single-attempt HTTP path, not from a profile.

- **CPP-3** (Medium, High when many workers share few hosts · M · verified at sampled sites). The upstream `Host` `shared_ptr` is taken by value at every hop from load-balancer pick to pool-ready: 19 copies per request, 3 of them kept (`envoy/upstream/load_balancer.h:63`, `source/common/router/upstream_request.cc:411`). `ClusterInfo` adds 9 and the route 4 (`source/common/router/router.h:547`). Each copy is two atomic operations on a control block all workers share. **Change:** `const&` on the borrow-only hops, `std::move` at the three sinks, reference-returning `host()` and `cluster()` accessors. Interface signatures change.
- **CPP-1** (Medium · S · verified). The router takes two reader locks and copies the TLS context `shared_ptr` on every request, to compute a boolean that is read only when scheme matching to upstream is on (`source/common/router/router.cc:848`, `source/common/upstream/upstream_impl.h:167`, `source/common/tls/client_ssl_socket.cc:100`). **Change:** Read `shouldSchemeMatchUpstream()` first and touch the factory only then.
- **CPP-2** (Medium · S · verified). `ClusterEntry::httpConnPool` wraps a closure in a `std::function` per request. On `newStream` it builds a second one with four captures for `maybePreconnect`, which returns at once because the preconnect ratio defaults to 1.0 (`source/common/upstream/cluster_manager_impl.cc:1115`, `:1157`). **Change:** `absl::FunctionRef` for the synchronous callback; skip the closure when the ratio is at most 1.0.
- **CPP-6** (Medium · S · verified). ## String usage patterns

The default request path still makes about ten runtime lookups by a 40 to 60 character key and one to three avoidable string allocations. The rest of the string cost sits in specific features: `uri_template` rewrite, query and cookie parsing, `normalize_path`.

- **STR-1** (High · S · verified). Circuit-breaker limits are read from runtime by string key about seven times per request. `ManagedResourceImpl::inc` and `decBy` each call `max()` three times (`source/common/upstream/resource_manager_impl.h:34`, `:55`), and `max()` is `runtime_->snapshot().getInteger(key)` (`source/common/common/basic_resource_impl.h:39`). - **STR-2** (Medium · S · verified). `uri_template` rewrite compiles two RE2 regexes and re-parses the template on every request (`source/extensions/path/rewrite/uri_template/uri_template_rewrite.cc:48`, `:58`). The only per-request regex compile in the tree. **Change:** Build the regex and the rewrite segments once per route. The matcher beside it already holds the same compiled regex.
- **STR-3** (Medium · S · verified). `x-request-id`: `uuid()` returns a 36-byte `std::string`; `getInteger` copies the header and takes `substr(0, 8).c_str()` (`source/extensions/request_id/uuid/config.cc:66`); `setTraceReason` copies it again. - **STR-4** (Medium · M · verified). Query strings and cookies are parsed into a map of strings to read one key (`source/common/http/utility.cc:496`, `:527`). - **STR-7** (Medium · S · verified). - **STR-12** (Low · S · verified). ## HTTP/1 and HTTP/2 codecs

Both codecs copy received body bytes whenever the body does not fill a whole buffer slice, which means every HTTP/2 DATA frame and every chunked HTTP/1 body. The sweep for this area did not finish, so this section holds only what the second pass read directly. Balsa internals, HPACK and per-stream setup were not audited.

- **CODEC-1** (Medium for HTTP/2 bodies · L · verified). HTTP/2 receive copies every DATA payload byte into the stream's buffer (`source/common/http/http2/codec_impl.cc:1168`). The payload sits inside a read slice between 9-byte frame headers, so it cannot be moved. **Change:** Needs slices that can be split or shared without a copy; see the note under the table.
- **CODEC-2** (Medium for chunked bodies · L · verified). HTTP/1 receive moves a body slice only when the body covers the whole slice, and copies otherwise (`source/common/http/http1/codec_impl.cc:745`). Chunked bodies rarely qualify, because chunk-size lines sit inside the slices. **Change:** The same enabler as CODEC-1.
- **CPP-7** (Medium · S · verified). HTTP/2 `updateActiveStreamsOnEncode` erases and re-emplaces the stream's list node on every `encodeHeaders`, `encodeData` and `encodeTrailers` (`source/common/http/http2/codec_impl.h:794`): one free and one allocation per call, to move a node to the front. **Change:** A same-list `splice`, skipped when the stream is already first.
- **CODEC-3** (Low · M · verified). HTTP/2 decode looks each header name up twice: once in the codec's static name table, then in the header map's trie inside `addViaMove` (`codec_impl.cc:2032`). **Change:** One lookup that returns the slot for both.
- **CODEC-4** (Low · S · verified). Per HTTP/2 `dispatch`: a clock read for `last_received_data_time_`, which only client connections with a keepalive idle interval use (`codec_impl.cc:1107`); a `std::function` scope guard; on servers a runtime flag read by name (`codec_impl.cc:2639`). **Change:** The dispatcher's approximate time, or skip when unused; `absl::Cleanup`; latch the flag.

Findings from other sections that land in the codecs: HTTP/2 encode copies each owned header name and value twice (HUSE-1); DATA frames go out as a 9-byte slice plus payload, which defeats slice alignment under TLS (NET-1); HTTP/1 upstream schedules a no-op pool callback per response (UPS-4).

CODEC-1, CODEC-2, the retry-buffer copy in HCM-10 and the GRO segment copy in QUIC-12 share one cause. A `Buffer` slice owns its storage exclusively, so a sub-range cannot move to another buffer without a copy. Ref-counted slice storage would remove all four, but it changes a central class and needs a design and a body-throughput benchmark first.

## QUIC, HTTP/3 and QUICHE

The UDP receive path spends more on setup than on the packet: each `recvmmsg` call builds 16 buffers with about 54 heap allocations, and every read event makes a second call that only returns `EAGAIN`. Header names are then copied up to five times between the wire and the header map.

### Envoy side

- **QUIC-1** (High for HTTP/3 and UDP · S and M · verified). UDP receive, the downstream default: each `recvmmsg` call builds 16 `OwnedImpl`s, 16 reservations and 16 per-packet info structs, whatever the number of packets returned (`source/common/network/utility.cc:647`). The loop then calls again until `EAGAIN`. **Change:** Treat a short batch as drained. Keep the 16 buffers across iterations and events and refill only the consumed ones.
- **QUIC-7** (Medium · S · verified). Request headers: a throwaway `LowerCaseString` per header name, then `addCopy`, then a second full validation pass (`source/common/quic/envoy_quic_utils.h:102`). The TODO there already asks to avoid the copy. **Change:** Build `HeaderString`s and call `addViaMove`, as the HTTP/2 codec does; drop the duplicate validation.
- **QUIC-4, QUIC-5** (Medium · S · reported). Per received packet: two heap `Address::Instance`s with string formatting (`source/common/network/io_socket_handle_impl.cc:534`), and a 1 KB empty `OwnedImpl` for saved control messages that is move-constructed three times (`source/common/network/utility.cc:549`). **Change:** Remember the last local and peer address; pass the buffer by rvalue or make it a small inline vector.
- **QUIC-6** (Medium · S and L · reported). HTTP/3 downstream deep-copies `StreamInfo` per request for ACK-deferred access logging (`source/common/quic/envoy_quic_server_stream.h:50`). HTTP/1 and HTTP/2 pay none of it. **Change:** Skip when no handlers are registered; hand the stream info over in place of the copy.
- **QUIC-2** (Medium · S · reported). `EnvoyQuicPacketWriter` builds four heap `Address::Instance`s per sent packet, two of them for a call the default writer ignores (`source/common/quic/envoy_quic_packet_writer.cc:38`, `:62`). Applies to upstream HTTP/3 and non-GSO listeners. **Change:** Cache the last self and peer conversion in the writer.
- **QUIC-11, QUIC-12** (Medium · M · reported). Upstream HTTP/3 sends one `writev` per packet; client connections have no batch writer. GRO receive allocates 64 KB per `recvmsg` and copies each segment into a fresh buffer (`source/common/network/utility.cc:579`, `:617`). **Change:** A client packet-writer extension that returns QUICHE's GSO batch writer; one reusable receive buffer with segments passed as views.
- **QUIC-18** (Low · S · verified for the body path). `OnBodyAvailable` heap-allocates an `OwnedImpl` and copies each readable region out of the sequencer (`source/common/quic/envoy_quic_server_stream.cc:281`). Each stream also does three to five `dynamic_cast` cross-casts (CPP-15). **Change:** Stack-allocate the buffer; `static_cast` to the concrete session. A zero-copy read needs a QUICHE API.
- **QUIC-9, QUIC-10, QUIC-13** (Low to Medium · S · verified for the stream flag). Per packet: the listener's `enabled_` check goes through the shared runtime snapshot (TLS-1); `runtimeFeatureEnabled` is called by name per packet, per STREAM frame and per body read (`source/common/quic/envoy_quic_server_session.cc:328`, `envoy_quic_server_stream.cc:275`); a stats counter is bumped per sent packet. **Change:** Latch per read event or per session; accumulate the counter per write burst.
- **QUIC-3** (Medium · S · reported). Latency, not CPU. A QUIC alarm that is due now is clamped to 1 µs and libevent rounds that up, so on an idle worker a deferred write can wait up to 1 ms (`source/common/quic/envoy_quic_alarm.cc:15`). **Change:** Pass 0 when the deadline has passed.

### QUICHE, for upstream

- **QUIC-8** (Medium · S). Every decoded header block is deep-copied into `header_list_` and then cleared (`quiche/quic/core/http/quic_spdy_stream.cc:656`). 10 to 20 allocations per request and per response. **Change:** `std::move` the list in `OnHeadersDecoded`.

- **QUIC-16** (Low · S). `QuicSpdyStream` frame-header bookkeeping allocates per acked STREAM frame and per DATA frame (`quiche/quic/core/http/quic_spdy_stream.cc:1077`). **Change:** Early-out on empty or disjoint ranges without a temporary set.

## Request path

Before any configured filter runs, the connection manager and router make about 34 heap allocations, 30 `shared_ptr` copies of cross-thread objects, 26 clock reads and 12 libevent timer calls per request. The stream idle timer is the largest single item.

- **HCM-1** (High · S then M · verified). The stream idle timer is re-armed on every header and body event (`source/common/http/conn_manager_impl.cc:1290`). It is a scaled range timer whose `enableTimer` disables first (`source/common/event/scaled_range_timer_manager_impl.cc:54`), so each reset is a libevent delete plus add. A GET with one response chunk makes about 12 timer calls; each further body chunk adds two per direction. **Change:** Step one: skip the call when the dispatcher's cached time and the timeout are unchanged since the last arm. Step two, as the TODO there suggests: store last activity only and re-arm from the timer callback.
- **HCM-4** (Medium · S each · verified for the proto, reported for the rest). Per-stream allocations for features a normal request never uses: a histogram timespan, a stream-id provider, an on-demand RDS requester, two objects for the decoder handle, an empty pool config proto (`source/common/router/router.cc:1042`), list-node churn in `resetOtherUpstreams`, two attempt vectors. Nine allocations. **Change:** Each has a local fix: derive it, embed it, or create it on first use.
- **HCM-5** (Medium · S · verified). The router stores host-selection start and end times in a string-keyed map on every request (`router.cc:742`, `:1097`): two heap keys, two table allocations, two clock reads. The only reader is `%COMMON_DURATION%` with custom keys. **Change:** Two typed `std::optional<MonotonicTime>` fields that `getValue` maps the names onto.
- **HCM-6** (Medium · S · reported). Five runtime snapshot reads per request in the HCM and router, some ahead of a cheaper test: `OptionallyDelayClose` before `skip_delay_close`, the premature-reset keys before the counters they guard (`conn_manager_impl.cc:354`, `:877`, `:915`). **Change:** Reorder the conditions and four of the five reads go away. TLS-1 removes the refcount cost of the rest.
- **HCM-7** (Medium · M · reported). On routes with a retry policy, `RetryStateImpl` is fully built per request: three vector copies, host predicates, a backoff strategy and a runtime read, none used unless the upstream fails (`source/common/router/retry_state_impl.cc:67`). **Change:** Reference the policy's vectors; create predicates and backoff at the first retry.
- **HCM-8** (Medium on long route lists · S · verified). The route scan evaluates `matchRoute()` (runtime fraction, headers, query, TLS, metadata) before the constant-time path compare (`source/common/router/config_impl.cc:1527`). **Change:** Swap the operands for prefix, exact-path and path-separated-prefix routes.
- **HCM-9** (Medium · S · reported). Every async client stream builds a `NullRouteImpl`: four to seven allocations, up to three copies of the cluster name and a `NullSpan` (`source/common/http/async_client_impl.cc:117`). Paid per ext\_authz, ratelimit, ext\_proc or mirrored request. **Change:** Hold the cluster name by reference; one `make_shared` for route, entry and policy.
- **HCM-10** (Medium, High for uploads · L · reported). While a retry or internal redirect is still possible, each request body chunk is deep-copied for the upstream (`router.cc:1234`). **Change:** Share the kept slices through ref-counted fragments. Needs a lifetime design.
- **CPP-11** (Medium for those clusters · S · reported). With `upstream_config` set on a cluster, the router does a factory lookup and unpacks an `Any` on every request (`router.cc:1026`). **Change:** Resolve the factory and message once per cluster.
- **HCM-13, HCM-14, HCM-15** (Low · S · reported). An unlatched runtime flag in the filter manager constructor; `QueryParameterMatcher` copies the value and reads a flag per candidate route; weighted-cluster routes allocate a route object per request. **Change:** Local fixes named in each finding.

No benchmark exercises this path end to end today. `filter_manager_benchmark` stubs the idle timer and `config_impl_speed_test` covers route lookup only, so HCM-1, HCM-4, HCM-5 and HCM-7 need a new benchmark: one request through a real `ConnectionManagerImpl` and router, with a real dispatcher and an instant fake pool.

- **UPS-1** (Medium · S · verified for the preconnect closures, reported for the rest). ## Buffer, network I/O and TLS

A one-record TLS request costs three `recv` calls where one would do, and every plaintext read event ends with a wasted `readv`. Both can be fixed inside the transport-socket layer.

### Socket syscalls

- **IO-1** (High · M · verified). TLS read. BoringSSL asks the BIO for the 5-byte record header, then for the body, and the BIO does one `recv` per ask (`source/common/tls/io_handle_bio.cc:34`). `sslReadIntoSlice` then calls `SSL_read` again and gets `EAGAIN` (`source/common/tls/ssl_socket.cc:93`). R records cost 2R+1 syscalls. **Change:** Read ahead inside the BIO with a two-iovec `readv`: the caller's buffer plus a small scratch slice. Serve later asks from the scratch slice.
- **IO-2** (High · M · verified). Plaintext read. `RawBufferSocket::doRead` loops until `EAGAIN` (`source/common/network/raw_buffer_socket.cc:21`). The reservation is 128 KB, so the first read is almost always short and the second is wasted. **Change:** Stop after a short read. Register `EPOLLRDHUP` with read so a FIN queued behind the data is still seen.
- **IO-3** (High · S · verified). TLS write. `linearize(16384)` before each `SSL_write` (`source/common/tls/ssl_socket.cc:357`) leaves the slice chain misaligned for good: one 16 KB allocation and copy per 16 KB sent. **Change:** Write the contiguous front slice once to realign. The fix is described in [A Copy That Never Stops Copying]({{< ref "envoy-tls-linearize.md" >}}): a median 10.3% less CPU on the affected path. It is still not upstream.
- **IO-4** (Medium · M · verified). Each `readDisable` transition does `EPOLL_CTL_DEL` then `EPOLL_CTL_ADD` in edge mode (`source/common/event/file_event_impl.cc:102`). Hit on every watermark flap, TCP-proxy connection setup and pipelined HTTP/1 request. **Change:** Keep one kernel registration and mask events in user space. Shares the `EPOLLRDHUP` work with IO-2.
- **IO-5** (Low · M · verified). TLS write. One `send` per 16 KB record (`source/common/tls/io_handle_bio.cc:67`). **Change:** Coalescing costs a ciphertext copy per record, so it trades one syscall for one 16 KB `memcpy`.

**IO-1.** BoringSSL reads exactly the bytes it still needs (`ssl/ssl_buffer.cc:152`): first the 5-byte header, then header plus ciphertext (`ssl/tls_record.cc:113`, `:142`). `SSL_set_read_ahead` is a no-op there. The fix stays in `io_handle_bio.cc`: read into `[caller buffer, 4 KB scratch]` in one `readv`, and take the scratch slice from the slice free list only while it holds data. A small request then needs one syscall instead of three; bulk data needs one per record instead of two, and only the read-ahead bytes are copied twice.

**IO-2.** `epoll(7)` states that a short read on a stream socket means the queue was empty, and nginx relies on it together with `EPOLLRDHUP`. The catch is a FIN that arrived before the read: no further edge fires, so EOF would be missed. Envoy asserts today that read and closed events are never requested together (`source/common/network/connection_impl.cc:735`). The change is to always register closed and, when it fires while reading is enabled, read to EOF instead of closing at once.

**IO-4 is not a per-request cost.** The HTTP/1 codec read-disables the connection only when pipelined data is waiting (`source/common/http/http1/codec_impl.cc:1300`), not for every request. The TODO at `file_event_impl.cc:94` already asks for this optimization.

A search of upstream issues and pull requests on 2026-11-24 found no earlier attempt at IO-1 or IO-2. The open io\_uring work ([#48282](https://github.com/envoyproxy/envoy/pull/48282)) is the other route to fewer syscalls.

### Buffers, connections and TLS internals

- **NET-1** (High for HTTP/2 over TLS · L · verified). The IO-3 fix cannot help HTTP/2 over TLS. `SendDataFrame` puts a 9-byte frame-header slice in front of every DATA payload (`source/common/http/http2/codec_impl.cc:1974`), so the write buffer is `[9][16384][9][16384]` and every record is linearized: a 16 KB allocation and copy each. **Change:** Give payload slices front headroom so the frame header is prepended in place, or write one record per slice with record batching in the BIO.
- **NET-3** (Medium on mTLS meshes · S · reported, open since August). The TLS connection-info cache treats an empty result as not yet computed (`source/common/tls/connection_info_impl_base.cc:21`). A peer with no URI SAN, or no client certificate, is re-decoded on every accessor call from XFCC, RBAC principals, ext\_authz and access-log commands. The `create` callback is a `std::function` taken by value on every call, hit or miss. Deliberate since [#40179](https://github.com/envoyproxy/envoy/issues/40179), for values read before the handshake ends. **Change:** A "final" bit per entry, set once the handshake is complete; template the callable.
- **NET-4** (Medium for short-lived connections · S · verified). Every accepted TCP connection calls `getsockopt(TCP_INFO)` to record a round-trip time that only `%DOWNSTREAM_CX_RTT%` reads (`source/common/listener_manager/active_tcp_listener.cc:115`). **Change:** Latch "RTT requested" when that formatter is configured and skip the call otherwise.
- **NET-5** (Medium · M · reported, open since August). `Slice` is 112 to 128 bytes, so an empty `OwnedImpl` is about 1 KB of constructed state (`source/common/buffer/buffer_impl.h:374`, `:567`). One is built per HTTP/2 frame, per UDP packet and per end-of-stream signal, and two per connection. **Change:** Move the three rarely used members behind one pointer, which takes `Slice` to 48 bytes. Keep the ring at 8 and the `std::list` splice, which an earlier review found necessary.
- **NET-6** (Medium · S or L · reported). Each read and write event updates connection byte stats with three to five atomic operations on lines shared by all workers (`source/common/network/connection_impl.cc:49`). That is 12 to 16 per proxied request. **Change:** STATS-4 removes two of every three. The full fix is per-worker counter shards.
- **NET-7** (Low · M · reported). Every read reservation heap-allocates its slice owner and moves eight slices through the free list (`source/common/buffer/buffer_impl.cc:413`). Plain TCP does it twice per read event because of IO-2. **Change:** Embed the owner in `Reservation`; reserve one slice unless the last read filled its reservation.
- **NET-8** (Low, Medium under connection churn · S and M · reported). `tls_inspector` builds and frees a whole `SSL` object per connection and zero-fills a 16 KB peek buffer. The listener-filter phase adds two `epoll_ctl` calls and one extra `recv` (`source/extensions/filters/listener/tls_inspector/tls_inspector.cc:96`). **Change:** `SSL_parse_client_hello` on the peeked bytes with one shared `SSL` per config; an uninitialized peek buffer.
- **NET-10** (Low · S · reported). Creating an `Address::Instance` is two allocations plus eager string formatting, with `inet_ntop` and `fmt::format` for IPv6 (`source/common/network/address_impl.h:81`). One or two per accepted connection, one per XFF parse, two per UDP packet. **Change:** One allocation through a passkey constructor; hand-rolled IPv6 formatting.

Smaller per-connection items: filter-chain matching copies the SNI into a `std::string` once per label (NET-11); the listener-filter factory `std::function` is copied per filter because `auto` drops the reference at `source/server/configuration_impl.cc:54` (NET-12); the global connection limit check takes a ref-counted runtime snapshot per accept (NET-13); runtime flags are read in connection and handshake constructors (NET-14).

## Extensions

On an AI endpoint the protocol manager re-serializes every request and runs every response through decode and re-serialize by default, even when no AI filter needs it. Outside AI, the largest fixed costs sit in the shared gRPC side-call helpers, not in the filters that use them.

### AI protocol manager and MCP

Paths below are under `source/extensions/filters/http/ai_protocol_manager/` unless they start with `source/`.

- **EXTB-1** (High · M · verified). With the default `reserialize_body: ALWAYS`, the sink walks the request DOM twice: a counting pass, then an emit pass (`request_filter_manager.cc:175`). Each JSON node costs a coroutine, an `nlohmann::dump()` and a deep copy (`serializer.cc:115`). It runs with an empty filter list too (`filter.cc:548`). **Change:** Track whether any filter changed the document and replay the received bytes when none did. For real rewrites, one synchronous writer that computes offsets in the same pass.
- **EXTB-2** (High · S · verified). Every 2xx SSE or JSON response on an AI endpoint is decoded to a DOM and re-serialized once a filter manager exists (`filter.cc:574`, `:644`), even when no AI filter handles responses. `content-length` is dropped. **Change:** Decide before touching the body: when every stage bows out at start, tear the pipeline down and return `Continue`.
- **EXTB-3** (High · M · verified). Re-serialized SSE: each event leaves as four or five separate injects, each with its own `OwnedImpl`, coroutine and scheduled callback (`sse/sse_event_codec.cc:451`, `buffer_manager.cc:232`). A parser and a buffer manager are built per event. **Change:** Serialize an event into one buffer and inject once per `onData` batch. One reusable parser per stream.
- **EXTB-4** (Medium · M · verified). Token usage on OpenAI and Gemini streams builds a new parser and a full DOM for every event, to learn that `usage` is absent in all but the last (`response_handler.cc:286`). **Change:** A handler that skips string capture and builds a DOM only under the usage member.
- **EXTB-5** (Medium · S · verified). In-memory replay zero-fills a scratch array, copies the chunk into it, then copies it again into a buffer, per 64 KiB (`buffer_manager.cc:434`). The body and two DOMs stay resident for the whole stream. **Change:** Copy once into a reserved slice, or move the slices for the final replay. Release at sink completion.
- **EXTB-8** (Medium · S · verified). A binding supplied through filter state is parsed, and its RE2 patterns compiled, on every request (`ai_filter_state.cc:36`). **Change:** Intern parsed bindings in a bounded cache keyed by source text.
- **EXTB-6** (Medium · M · reported). The JSON cursor copies each object key four times and inserts it into a per-depth hash set (`source/common/json/wuffs_json/wuffs_json_cursor.cc:250`, `:312`). It has no `reset()`, so per-event users rebuild it. **Change:** Let a handler opt out of duplicate tracking; add `reset()`.
- **EXTB-7** (Medium · L · reported). Unary JSON responses are flattened, unflattened, flattened again and dumped (`flattening_json_codec.cc:124`). The transcoder collects all fields with no cap. **Change:** Hand unary filters the DOM and serialize once.
- **EXTB-10** (Medium · M · reported). `mcp_router` unpacks an `Any` and rebuilds its per-cluster config on every request (`source/extensions/filters/http/mcp_router/mcp_router.cc:140`), and buffers whole JSON tool responses (`backend_stream.cc:139` in the same directory). **Change:** Parse cluster metadata once through a typed-metadata factory. Stream single-backend responses.
- **EXTB-12** (Medium · M · reported). `sse_to_metadata` copies each SSE byte three to four times and builds a DOM per event (`source/extensions/filters/http/sse_to_metadata/filter.cc:76`, `:99`). **Change:** Scan complete events in place; evaluate selectors with a SAX pass.
- **EXTB-9, EXTB-11** (Low · S · reported). Schema validation builds a path string per node and formats an error for each `oneOf` miss on the success path (`schema.cc:238`, `:334`). The MCP field extractor does a set insert and a path string per key (`source/extensions/filters/http/mcp/mcp_json_parser.cc:336`). **Change:** Render paths only on error; pre-check a candidate's JSON type; match paths by segment.

### Authorization, policy and traffic filters

- **EXTA-1** (Medium · S · verified). The ext\_authz and ratelimit gRPC clients call `DescriptorPool::FindMethodByName` in their constructor, once per stream, under the generated pool's reader lock (`source/extensions/filters/common/ext_authz/ext_authz_grpc_impl.cc:97`, `source/extensions/filters/common/ratelimit/ratelimit_impl.cc:25`). **Change:** Resolve the descriptor once in a function-local static.
- **EXTA-2** (Medium · S · verified). The cached gRPC client lookup re-arms the eviction timer and reads the clock twice whenever the hit entry is the LRU tail. With one service it always is (`source/common/grpc/async_client_manager_impl.cc:227`). **Change:** Leave the timer alone on access and recompute the next expiry when it fires.
- **EXTA-3** (Medium · M · verified). RBAC writes its enforced result into dynamic metadata on every request, about nine allocations (`source/extensions/filters/http/rbac/rbac_filter.cc:281`). **Change:** An API knob to skip the enforced fields, or a filter-state object in place of the `Struct`.
- **EXTA-4, EXTA-6** (Medium · S and M · reported). ext\_authz copies each header into the CheckRequest through a temporary key, a sanitized copy, then `find` and `operator[]` (`source/extensions/filters/common/ext_authz/check_request_utils.cc:156`). The HTTP service then converts the proto back into headers. **Change:** One `try_emplace`, validate UTF-8 before copying, capture by reference. Let the HTTP client build its headers from the request map.
- **EXTA-5** (Medium · S · reported). jwt\_authn deep-copies the payload `Struct` two or three times per request with `payload_in_metadata`, cache hit included (`source/extensions/filters/http/jwt_authn/verifier.cc:61`, `filter.cc:112`). **Change:** `Swap` into the stream's metadata entry when it is empty.
- **EXTA-7** (Medium · S · verified). Every typed gRPC message allocates a second 4 KB slice for its 5-byte frame header, because the payload slice has no headroom (`source/common/grpc/common.cc:191`, `:297`). **Change:** Reserve `size + 5` and serialize at offset 5.
- **EXTA-8** (Medium · S · reported). A unary Envoy-gRPC call allocates two `NullSpan`s, a span name, a path string and an unused 1 KB buffer (`source/common/grpc/async_client_impl.cc:166`, `:468`). **Change:** Pass the span in; cache path and span name per method.
- **EXTA-9** (Medium · S · reported). ext\_proc deep-copies its per-route config, then re-serializes and hashes a per-route `GrpcService`, on every request (`source/extensions/filters/http/ext_proc/ext_proc.cc:2242`). **Change:** Build the hash key in the per-route config constructor, as ext\_authz does.
- **EXTA-10, EXTA-11** (Medium for body modes · M · verified (decoder)). `Grpc::Decoder` copies every received message into a new buffer (`source/common/grpc/codec.cc:64`). ext\_proc streamed bodies end up with five copies per mutated chunk, plus an empty `metadata_context` per message (`ext_proc.cc:1452`, `:1692`). **Change:** Drain the 5-byte header and `move` the payload slices. Skip the empty submessage.
- **EXTA-12** (Medium on many cores · S · reported). local\_ratelimit does four to six refcount operations per request on the bucket shared by all workers. Wildcard descriptors take an exclusive lock per lookup (`source/extensions/filters/common/local_ratelimit/local_ratelimit_impl.cc:203`, `:394`). **Change:** Move instead of copy, raw pointers for static buckets, hash outside the lock.
- **EXTA-13** (Medium · M · reported). The compressor creates codec state per response. With zlib-ng that is about 160 KB allocated and 136 KB zeroed for gzip (`source/extensions/compression/gzip/compressor/config.cc:62`). **Change:** A small per-worker free list with `deflateReset`.
- **EXTB-14** (High where configured · M · verified). statsd sinks: every histogram sample on a worker takes the symbol-table lock to decode the stat name, formats a line and, over UDP, issues its own `sendmsg` (`source/extensions/stat_sinks/common/statsd/statsd.cc:138`, `source/common/stats/symbol_table.cc:223`). **Change:** A per-worker datagram buffer and a cached name per histogram.
- **EXTB-15** (Medium · S · reported). gRPC stats rebuild joined stat names and look up the scope on each charge, five times per unary RPC (`source/common/grpc/context_impl.cc:59`). **Change:** Latch the counters in the filter on first use.

Smaller items, all Low and local: unlatched runtime flags per chunk in ext\_proc and per path matcher in RBAC (EXTA-14); two `LowerCaseString`s per ext\_authz response header (EXTA-15); stat lookups by name in ip\_tagging, geoip and ratelimit (EXTA-16); jwt\_authn parsing the whole query for `access_token` (EXTA-17); `FractionalPercent::enabled()` building two protos per call (EXTA-18); a heap activation per CEL evaluation (EXTA-20); `metrics_service` copying a proto per stat at flush (EXTB-17).

### Access logs, tracing and stream info

- **ALOG-1** (High at 16 or more workers · M · verified). File and stdout access logs: `AccessLogFileImpl::write` takes one mutex per log line, shared by every worker that writes that path. Under the lock it updates two shared stats and copies the line (`source/common/access_log/access_log_manager_impl.cc:213`). All stdout loggers share one instance. **Change:** Batch per worker: append to a thread-local buffer and move it into the flush buffer once per event-loop iteration.
- **ALOG-6** (High with tracing at low sampling · M · reported). The OpenTelemetry and Zipkin drivers do full span bookkeeping for unsampled requests: 25 to 35 allocations per request for OpenTelemetry, 6 to 12 for Zipkin (`source/extensions/tracers/opentelemetry/tracer.cc:148`, `:383`). **Change:** Build attributes in place; keep ids as bytes until inject; return early from Zipkin `finishSpan` when unsampled.
- **ALOG-3** (High for that logger · S · reported). The OpenTelemetry access logger deep-copies its formatted attribute tree three times per record, four for the body (`source/extensions/access_loggers/open_telemetry/substitution_formatter.cc:101`). About 250 to 300 extra allocations with 20 attributes. **Change:** Build in place into the destination proto.
- **ALOG-2** (Medium · S · reported). Upstream and async-client span finalization does all its tag work for spans that will not be exported. [#44614](https://github.com/envoyproxy/envoy/issues/44614) added the early exit for downstream spans only (`source/common/tracing/http_tracer_impl.cc:205`). **Change:** The same early exit in `finalizeUpstreamSpan` and `finalizeSpan`.
- **ALOG-5** (Medium · S each · reported). `StreamInfo` makes six avoidable allocations per proxied request: two placeholder `BytesMeter`s, an eager request-level `FilterState`, the stream-id provider and two attempt vectors (`source/common/stream_info/stream_info_impl.h:583`). **Change:** Create each on first use.
- **ALOG-12** (Medium for ALS · M · reported). A gRPC access log entry costs about 50 allocations, a full `ByteSizeLong()` walk and 28 response-flag probes (`source/extensions/access_loggers/grpc/grpc_access_log_utils.cc:52`). **Change:** A per-thread arena for the batch; fill the entry in place; exit early when no flag is set.
- **ALOG-4, ALOG-11** (Medium · S · reported). The file logger still calls `format()`, a fresh string per line, although `formatTo()` exists (`source/extensions/access_loggers/common/file_access_log_impl.cc:17`). A few providers still build temporaries: `UPSTREAM_CLUSTER`, `RESPONSE_CODE_DETAILS`, metadata and typed `FILTER_STATE`. **Change:** Format into a reused buffer; finish the provider conversions.
- **ALOG-15** (Low to Medium · S · reported). A local reply costs six to eight allocations: `std::function` copies, an owner object, status and body formatted twice (`source/common/http/filter_manager.cc:523`). This path is hot when Envoy answers 429 or 503 under overload. **Change:** Capture by reference; set `:status` once; skip the body string when no mapper is configured.

## Build and toolchain

Release binaries are built with plain `-c opt`: no profile feedback, no LTO, and the baseline instruction set. An upstream experiment measured 21% more requests per second from PGO alone, which is larger than any single code change in this report.

- **BLD-1** (High · L · measured upstream, not here). No profile-guided optimization. The release build is `bazel build -c opt --stripopt=--strip-all` (`ci/do_ci.sh:1057`). **Change:** Add a PGO config (instrumented, or sampled from production `perf` data) and a published training workload. The 2023 experiment in [#25500](https://github.com/envoyproxy/envoy/issues/25500) went from 5,200 to 6,300 RPS on one worker with Clang 14.
- **BLD-2** (Medium · M · not measured). No LTO. One-line accessors defined in `.cc` files (header map, stream info, buffer) cannot inline across translation units. **Change:** ThinLTO on release links. Open since 2018 as [#4159](https://github.com/envoyproxy/envoy/issues/4159).
- **BLD-3** (Low · S · not measured). No `-march`. Abseil's CRC32 string hash is compiled in only under `__SSE4_2__` or `__ARM_FEATURE_CRC32` (`absl/hash/internal/hash.h:106`, `:126`), so every `flat_hash_map<std::string>` lookup uses the portable fallback. **Change:** Evaluate an `x86-64-v2` and an `armv8.2-a` baseline for release images. Drops CPUs older than about 2009 on x86.

BLD-1 and BLD-2 change no source and stack with everything else here, so they are worth measuring first with the same paired A/B method used for the code changes.

## Checked and already fine

These looked suspicious and are not worth re-auditing. Several were hypotheses of this audit that the code refuted.

- HTTP/1 does not read-disable the connection per request, only when pipelined data is waiting (`source/common/http/http1/codec_impl.cc:1300`).
- Filter config names are `string_view` end to end. `filterDisabled` and `mostSpecificPerFilterConfig` exit early on empty maps (`source/common/router/per_filter_config.cc:126`).
- `route()` and `clusterInfo()` filter callbacks return `OptRef`, not a `shared_ptr` copy.
- Virtual-host lookup lowercases the host only when it holds an upper-case byte (`source/common/router/config_impl.cc:2204`). `RouteMatchContext` caches path variants, query parameters and cookies once per request.
- Stat-name joins on the scope path no longer allocate; the joiner has a 24-byte inline buffer.
- FilterState well-known keys use an indexed array, and lookups on the usually empty map do not hash.
- Router `fromFilterState` runs once per request and returns null without filter state. An earlier check reached the same result.
- `WatermarkBuffer` callbacks are inline `absl::AnyInvocable`s. Buffer memory accounts are null by default.
- Connection writes are coalesced per event-loop iteration by design. HTTP/2 DATA send moves slices without a copy, and `SslSocket::doRead` reads straight into buffer slices.
- Small-slice coalescing in `Buffer::move` copies only slices under 512 bytes. It was benchmarked and is deliberate.
- Range-for copies, non-`noexcept` moves and exceptions on data paths are clean, because clang-tidy already enforces them.
- `std::regex` appears only in stat tag extraction at stat creation. Every `parseRegex` call is config-time; STR-2 is the one per-request compile.
- TLS certificate selection, ALPN and session-ticket callbacks allocate nothing. Handshake stats are four lookups with no heap.
- The dynamic modules ABI returns views for headers and body.
- AI protocol manager: the request body reaches the JSON parser without `linearize` or `toString`; strings above the inline threshold are never materialized; the parsed document is shared by all AI filters.
- From the earlier pass: the `determinePriorityLoad()` copy is fixed, and the runtime check in `commonHandleAfterDataCallback` is now last in its chain.
